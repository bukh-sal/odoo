# ADR 0020: manager inspection and temporary upload validation

Date: 2026-10-29. Status: G2 revision11 contract checkpoint passed; runtime implementation/qualification pending. Parent: G5-X02, specification sections7.2-7.4 and20.1-20.3.

The remaining manager screens need installed state, complete declarative package details and upload validation. Use a separate additive `manager-view` major1 schema for these observations. Existing operations-request/view, canonical plans, approvals, host facade and old examples remain byte-identical. This avoids widening an approval protocol to carry archive bytes. G2 inventory revision11 records the schema, three examples and boundary tests before runtime work. Old clients continue using their existing routes; new clients require the accompanying versioned core/shell release. Unknown shapes remain rejected.

GET `/api/v1/operations/installed?offset=N` returns at most20 installations and a continuation offset. GET `/api/v1/operations/details?digest=sha256:...` returns the exact curated descriptor's normalized manifest, digest-bound provenance summary and trust description. Both require a current human application operator, session and client-release fence. The data comes from the existing published catalog/runtime projection and current native metadata, without importing package code. Report profile observation time/staleness separately from request time. Health is unknown unless independently observed; inconsistent metadata is degraded, never green success. Dependency state includes installed versions, required provider bindings and workspace availability. Details expose package claims as escaped text, not trusted HTML or fetched URLs. Digests bind bytes; publisher identity/signatures are not asserted.

POST `/api/v1/operations/validate-upload` accepts only `application/octet-stream`, with `X-MP-Artifact-Digest`, existing session CSRF and client-release headers. Maximum compressed body is100MiB, matching the current default archive limit; the existing validator also enforces500MiB expanded,10000entries, per-file/ratio/metadata limits. Filenames, paths, URLs, commands, approval and trust configuration are not accepted inputs. The server computes the digest again, acquires bytes into a private temporary directory, and invokes the same ArtifactValidator/staging path used by the local catalog. Temporary files are removed on every outcome. The result never installs, imports, builds, enrolls trust, writes the independent catalog or persists a package in the application database.

Upload results distinguish verified archive/inventory under the published curated policy, not_curated at the trust gate, and invalid archive/digest. Unknown bytes are not described as structurally validated when trust stopped inspection. Application metadata/results remain untrusted observations. The local operator retains their original file, independently validates/acquires it with the existing CLI, constructs/selects an immutable runtime separately, then uses the existing plan/request/exact local approval/apply path. A forged successful application result or published trust mirror grants no executor authority. Full-trust warnings remain explicit for native Python and same-origin plugin JavaScript; permission metadata is not confinement.

The internal shell request adapter may send a Blob body instead of JSON while retaining its existing session, CSRF, release headers, before/after release checks, cancellation and error envelope. This is not an extension of the public plugin-host facade. Operations adds a file input/result, installed table, paginated catalog selection and escaped details; native Odoo dialogs/notifications and standard CRUD View hosting remain. Canvas receives no product changes.

Required qualification: strict new shapes/unknown-authority rejection and retained golden consumers; valid/hostile/unapproved/digest/limit uploads using the real validator with no imports or retained files; current installed/details projection, absent/mismatched dependencies and honest health; role/CSRF/release denials, metadata escaping, actor changes, cancellation/disposal and pagination; actual versioned core activation and browser upload/details/native-view regression on a named disposable target. Source checks alone do not pass G5-X02. No previously completed native fixture may be replayed for this change.
