# ADR0043: finite authorization snapshots for native read serialization

Date: 2026-11-02. Status: core prerequisite qualified on native28/129; separate Notes/Labels adaptation and HTTP/10k performance qualification pending. Parent G-01c2, §§11.7/24.1; ID03 must remain qualified.

The actual current30Note/24A preflight with20 concurrent requests reports native list p952007ms and gateway list3478ms, with no errors. Actual installed profiling measures519SQL queries for24 native rows and816 for24 gateway rows; even one warmed scalar repeats four current-scope/feature/ownership/installation queries. R0's warm sequential session control remains31ms. This is a measured read-path amplification; the10k target is not passed and no target or resource limits are relaxed.

Keep every supported public entry/write and standalone cached field fully guarded. Add a private typed read serialization window for a finite, fully validated recordset. It binds the exact native environment, cursor, thread, backing user/sudo mode, authoritative typed carrier (actor/workspace/credential/action context), model and actual/virtual origin IDs. Native extensions may inspect additional context, so a changed environment cannot borrow the snapshot even with the same actor/workspace. It cannot be supplied through JSON/native RPC: the existing reserved context rejection remains. Reuse only this read authorization snapshot during the same serializer, for at most20ms before a full dynamic model guard runs again. Close it in `finally` and release the bound environment reference; a retained environment/token cannot keep authorization alive afterward. This is neither a client/result cache nor authority shared across workspace/principal operations.

Use the pinned native profiler `thread.query_hooks` seam to invalidate before non-plain reads, multi-statement SQL or mutation. Any pending ORM dirty state disables reuse; preserve the ordinary guarded path rather than flushing unrelated business writes to enable a cache. Core also flushes pending installation state before its existing state check. All subclass guards run when issuing/refreshing a snapshot. Native record rules and field/group permissions still run. Private policy memoization accepts booleans only, remains actor/workspace/model/window scoped, and expires/invalidates with the window. Explicit write permission/feature checks never use that policy memo.

The SQL hook is invalidation for cooperating supported serializers, not a SQL parser or sandbox. Arbitrary native code, sudo, raw SQL and side-effecting SQL functions remain fully trusted. Concurrent external policy changes are observed at the next normal entry or window refresh (maximum20ms snapshot lifetime, well inside the declared cached-authorization bound). Same-transaction supported ORM changes and ordinary mutating SQL invalidate immediately. Do not describe this as fresh SQL on every field within an already-authorized read batch.

Core20/identity1.5/SDK20 introduces the native read helper only, preserving every packaged artifact, schema and worker. After actual security qualification, any Notes/Labels DTO/optional-feature adaptations require a separate ordinary versioned plugin upgrade, with platform minimum20 and compatible declared dependencies. Native views remain the default; no frontend source or Canvas features change. Preserve all97 frozen contract files/eight rows; this is a private correction to read execution, not a contract-major or identity/ORM redesign.
