# ADR0032: populated dispatch lifecycle and recovery

Date: 2026-11-01. Status: implementation decision; not qualified. Parent F-01e, split into F-01e1 native queue support and F-01e2 external effects/credentials. Required by spec10.2–10.5,13,14,21.4,25.5F and MIG-06/08/09, OPS-02, JOB-03. Builds on ADR0025/0028/0029/0030/0031. No gate or acceptance credit from this decision.

Actual event qualification exposed a browser timer receiver defect. The narrow Shell1.9 source fix passes thirteen source tests and seven real browser scenarios against the unchanged a337 backend. It is not in the installed immutable image. A same-transaction native revision/CAS defect also needs a versioned Notes fix. Replacing this populated fixture with another empty installation would avoid the required upgrade/recovery problem. Implement the queue-aware path in the existing executor and independent review store, then use the ordinary approved upgrade to deploy and qualify these fixes on the retained fixture. Canvas remains unchanged; standard record screens remain native Odoo.

Current executor source stops ingress and the application and checks remaining database connections before checkpointing. It has no supported dispatch pause/reconciliation adapter. RestoreExecutor and UnchangedReleaseRecovery explicitly reject dispatch tables, even when empty. Those refusals must stay in force until the complete recognized profile is supported; removing the existence checks or accepting zero counts is insufficient. Keep the existing qualified no-dispatch behavior and exact-hash approval/journal boundaries.

Implement one private host-owned dispatch adapter. It may inspect and update scheduler/control/receipt metadata using bounded parameterized PostgreSQL operations; it must not replace native business-model writes with SQL or connect an external worker to the application database. Discover a known versioned schema/control identity and refuse partial or unknown layouts. Tie observations to the exact site/database/image/inventory/release, operator plan and native authority. An application queue, artifact, HTTP request or browser can never authorize this adapter. Reuse existing OS operation locks, private command capture, checkpoint manifests, expiring RecoveryReviews and conservative traffic-resumed journal fence. If any required public contract changes, record and qualify its G2 revision before consumers; private implementation is not an excuse for silent wire drift.

The required native sequence is:

1. Close ingress, pause dispatch and advance the control generation while waiting for existing native transactions holding shared control locks. Persist the before/after dispatch observations privately. Stop the managed application and require all remaining application database connections to drain. Detached computation can continue outside the database but its old claim must fail finalization. Never infer drain from an elapsed lease or stopped UI alone.
2. Fence outstanding job and event receipts. Preserve each job, event, delivery and consumer tombstone. Reconcile idempotent interrupted native work explicitly; hold unknown/incompatible work, and preserve non-idempotent uncertain outcomes for independent reconciliation. Advance/invalidate event receipt generations and close obsolete subscriptions so pause/resume and restore cannot admit an old acknowledgement. Pausing alone is insufficient because current event receipts do not carry the global dispatch generation.
3. Checkpoint coordinated native business/queue/dedup/control state and filestore while dispatch is fenced. Bind the private dispatch profile/state to the checkpoint and operation journal; replace the misleading no-dispatch checkpoint description only for this verified profile. Apply native/schema/metadata changes through the existing executor, then start exact guarded replacement workers with dispatch still paused.
4. Before release/dispatch resume, inspect current original-actor membership, role, feature, installation, technical credential, handler version, resource revision and named binding for retained work. Do not blindly rewrite an old serialized actor/binding/release context or silently select a newer service major. Explicitly classify resumable, held, cancelled and uncertain work with auditable reasons. Preserve semantic deduplication and the first correlation/causation trace. A compatible release needs a defined reviewed rebind/resumption policy, not permanent loss of all pending work.
5. Restore only into a fresh owned database, retaining the failed database and diagnostics. Carry current native authentication/revocations forward as ADR0028 requires, invalidate technical/session credentials and obsolete job/event claims, preserve the checkpoint's atomic business/effect/dedup relationship, and keep dispatch fenced. Reobserve source and restored state at prepare, start and the final readiness boundary. A separately reviewed exact state authorizes resume; a restored application's metadata cannot approve itself. Unknown or externally completed effects must prevent automatic replay.

Retained event history must be tested across an ordinary compatible release change. Current candidates/replay queries filter on the subscription's release digest, which may hide otherwise eligible seven-day events after an upgrade. Verify this with a targeted counterexample before editing. If confirmed, authorize current subscriptions through their current bindings and registered compatible payload schema while preserving immutable producer envelopes and native consumer deduplication; never rewrite historical producer release/identity or use a high-water event ID. A release epoch fences authority and stale mounts, rather than substituting for topic/schema/workspace authorization.

F-01e1 is complete only with real populated upgrade and pre/post-native-failure recovery, reviewed fresh restore/resume, late original claim/receipt denial, retained history/dedup, original-user authorization and protected-state evidence. Fix and version the pending Note revision defect as part of that controlled upgrade and exercise native same-transaction batch semantics. Requalify the actual host facade/native bus/browser wiring under the new immutable image; corrected-source harness evidence alone cannot close F-01b2.

F-01e2 remains mandatory: independently operated external runtimes, scoped audience/endpoint/image generations, credential rotation and a durable host-owned completion/reconciliation record must join the same restore/final-resume proof. A native-only helper or a permanently disabled external service cannot satisfy JOB-03, SVC checks or full G6 recovery. Do not erase external receipts, claim exactly-once remote effects, launch a runtime from registration metadata, or bypass independent executor approval.

Next discriminating output: a private dispatch snapshot/fence implementation with real rollback/old-claim/old-receipt and compatible-history counterexamples on the existing disposable fixture. Wire it into the existing lifecycle paths only after those invariants are proved. No new fixture, build or migration is authorized by the existence of this ADR alone; follow the already authorized exact operator workflow and evidence gates.
