# ADR 0025: fence restored effects through the final traffic-resume boundary

Date: 2026-10-29. Status: accepted and qualified for current G5 profile under G5-X06/MIG-09; affected MIG-06 requalified. Extends ADR0012. Native code remains trusted; no public request/plan/status contract or schema change.

Restore preparation already excludes job/outbox/API-key state unsupported by the G5 recovery profile. Its prior resume payload only observes release/registry/scoped metadata, which does not include queue tables, API keys or technical credentials. A readiness probe can also take time after initial decision verification. A safe earlier snapshot is insufficient evidence for opening traffic after effects or authority change.

Keep the existing independent CLI, RecoveryReviews, OS identity, expiring exact review, deployment/site locks and append-only journal. After loading a restored checkpoint and overlaying authority, check unsupported effects before switching configuration or starting the registry. At resume preparation and execution, require closed ingress; independently read public job/outbox table presence, API-key count, active technical credentials and external installation state. Unsupported state fails closed. Bind the clear r1-no-dispatch-v1 profile/effects snapshot and current canonical human authority digest into the private resume decision. After actual readiness, reobserve and compare at the final closed-traffic boundary before the conservative journal fence and edge start. Start expiry is not silently extended or reused as a mid-operation timeout.

Private reviews issued by the old host code lack these new bindings and require a fresh exact review. Existing public frozen DTOs are unchanged. This is host recovery code, so the current immutable application/native helper image is retained. Record source identity separately; verify supported real restore/resume as well as negative proposal/start/late-readiness paths.

The G5 profile deliberately refuses unknown dispatch state rather than claiming a generic queue reconciler. Its test fixture records harmless durable local completion receipts outside the restored DB and retains synthetic queued rows after explicit receipt-verified quarantine in an inert namespace. That is a bounded test resolution, not a shipped job adapter, automatic deletion policy or authorization to discard unknown user work. G6 must add real job/event/external-worker effect and credential reconciliation profiles and requalify shared MIG-08/09 before G7.

Application image and native Odoo views unchanged.
