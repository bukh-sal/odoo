# ADR0041: preserve empty Canvas arrays through native JSON storage

Date: 2026-11-02. Status: qualified on actual Canvas0.1.4/native27/dispatch126. Parent G-01d1, required reference compatibility.

The frozen board schema accepts `cards: []`, and the native model declares an empty-list default. Actual Canvas0.1.3 creation fails: the pinned Odoo Json field converts all falsy values to SQL NULL, while this field unnecessarily requires NOT NULL. The original PostgreSQL counterexample is retained under G7/native-paths-01. Scope qualification used a nonempty rollback fixture without discarding the defect.

Use ordinary optional native Json storage, as the existing Labels JSON field already does. Normalize its empty representation to `[]` in the board validator; the public DTO already does so. Keep strict public array validation, card validation, Note reference checks, ownership, roles and revision/CAS unchanged. Native schema update drops only `mp_example_canvas_board.cards` NOT NULL, preserves all rows, and requires no data rewrite or custom field implementation. Public null/non-array inputs remain invalid. Empty arrays are valid on create and on the frozen get/save service, including when clearing the last card.

Version Canvas0.1.3→0.1.4/native19.0.0.1.4 in a separate ordinary immutable plugin upgrade, with independent review and populated checkpoint/preservation. Core19/identity1.4, SDK, other plugin artifacts, worker and every public schema stay fixed. No Canvas UI expansion, new product behavior or ORM replacement is authorized by this correction. Qualify default/explicit empty creation, native reload, get/save nonempty→empty, stale CAS, viewer/foreign scope, strict invalid-array input and existing records after upgrade. G7/fresh-release qualification remains separate.

Qualification: ../evidence/G7/20261102-canvas4-source-01/qualification.json. Ordinary independently approved e6621f8d preserves one real nonempty preupgrade board and every other tracked datum under reviewed metadata/epoch changes. Nine actual native and ten actual HTTP checks include committed empty-array persistence and fresh authenticated reload, then original cards restored at revision3. Strict public null rejection returns the existing VALIDATION_FAILED code; one test expectation was corrected and resumed without repeating writes. Current native CRUD remains Odoo-owned. Full G7 is still open.
