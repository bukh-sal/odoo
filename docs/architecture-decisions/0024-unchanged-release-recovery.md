# ADR 0024: resume an unchanged release after a pre-mutation failure

Date: 2026-10-29. Status: implemented and qualified under G5-X06/MIG-01. Extends ADR0012's independent recovery review and process locks. No public request, plan, approval, status or host DTO changes; native Python remains fully trusted.

Actual fault600af7d9 after checkpoint and before OperatorStore.before_mutation leaves failed_before_mutation, stopped app/edge, no native child and an exact unchanged generation11/schema/business/configuration. Existing fresh-target restore intentionally requires recovery_required and cannot return this safe old release to service. Replaying the failed installation or restoring an unchanged database is not the recovery action required by section10.3.

Add a local prepare-unchanged-resume/resume-unchanged action to the existing plugin recover CLI. Use the same independently owned RecoveryReviews, OS identity, expiry/revocation, deployment/site locks and journal. A host-only recovery adapter reads the exact current independent configuration, fixed immutable runtime inventory, current native state and the original plan's complete base-state digest. It accepts only failed_before_mutation with mutation_started=false, normal installed modules, the independently selected guarded worker, no running operation child or other managed worker, and no replacement configuration. Changed authority/source/catalog/native metadata fails closed. Jobs/outbox/external runtimes remain excluded until G6's drain/reconciliation adapter is available.

Before any restart revoke the original approval permanently and journal the reviewed recovery attempt. Start only the selected existing worker if stopped, verify its guard/configuration/mount/network pins and readiness, independently reobserve the unchanged release, then record the conservative traffic fence before opening the existing edge. Do not rewrite the database, filestore, release lock/configuration, session authority or epoch. Leave the original operation failed_before_mutation; its installation did not complete. Repeated or interrupted recovery requires a fresh exact review of actual state. Retain failed stages/checkpoints/old images. This adapter never performs restore, so a previously opened traffic fence cannot authorize destructive rollback.

This is an operator capability: current application images and their pinned maintenance readers do not need changing merely to run a new host recovery command. Record host source identity separately from immutable runtime identity and requalify affected journal/review/CLI paths. Later distribution builds include the operator additions normally. Qualify the actual closed populated fixture, supported APIs/old client pin and public assets after resume, unchanged schema/data/files/authority, rejection of the failed original operation, and negative source/worker/mutation/review cases. This is not OS-process-crash or full MIG-08/09 qualification.
