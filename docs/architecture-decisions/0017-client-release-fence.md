# ADR 0017: pin loaded clients to their native release

Date: 2026-10-28. Status: implemented; native/API/browser and actual core rollout/recovery qualified. Protocol-1 changed-asset UI07 remains in progress.

Section19 requires native release mismatch to stop incompatible calls and lead to safe full reload. Mount generation and workspace policy generation are separate identities. Polling alone leaves a stale-write window; native advisory asset/bus notifications do not close it.

Introduce the explicitly named R1 **client-release transport protocol1**, frozen in inventory revision10. A document contains protocol1, site UUID, positive published release generation, release digest, inventory digest and a deterministic SHA256 token over those five fields. It is public compatibility metadata, never a credential, actor assertion or sandbox. Read all four DB parameters in one statement and require the inventory to equal the running image's inventory. Missing/inconsistent publication fails closed. Recovery uses a new epoch even when restoring old code.

No-store authenticated `/app` bootstrap embeds this document alongside native session info before immutable native asset URLs. The guarded worker and drained deployment path bind that bootstrap to its source image; old HTML retains its old pin. Authenticated no-store `GET /api/v1/client-release` returns current metadata without business dispatch/workspace selection. Effective context/catalog data also includes this release document. Never replace the client pin from a poll response.

After activation, `X-MP-Client-Release` must equal the current token for protected platform gateway routes and native dataset requests; model scope checks also enforce it for other HTTP entry points. Global session/workspaces/release discovery remain available for authentication and safe recovery. Trusted non-HTTP native execution retains typed scope semantics. Gateway mismatch is existing CONFLICT with details.field=client_release, outcome=not_started; native RPC uses a private AccessError subclass mapped by the host to the same error. Authorization, CSRF, CAS/idempotency, workspace/actor/feature checks remain independent and required. A caller able to read the current token gains no authority.

This is an explicit **transport migration**: old headerless business calls are rejected after activation. Existing JSON service1.0 DTOs, public host API1 and old golden plan bytes remain unchanged; do not claim headerless transport compatibility. This new transport's initial protocol is1; its introduction is recorded as a compatible schema inventory addition but an intentionally incompatible operational activation requiring client reload/tool updates. All current harness/API consumers must discover and pin the release once, never silently auto-adopt after a mismatch. Older native clients receive a controlled error and must reload/update. G2 freezes the new contract before deploying consumers.

Client mismatch is latched for that document. Block new calls immediately, abort old SDK/native requests, cancel pending dialogs/commands, dispose the custom page and ignore late responses. Capture existing bounded JSON draft snapshots only in memory with actor/site/workspace ownership. Use native notification and confirmation services for a sticky refresh action and explicit download/discard choice. Different-principal recovery clears the draft. Do not persist sensitive drafts automatically, replay unknown writes, reload automatically, or allow a retry to re-enable the old asset document. Keep optional Canvas and standard native list/form hosting.

Use ADR0016 for the actual versioned identity/core/shell backend rollout; static deploy remains forbidden. Qualification must prove pure identity/headers/malformed inputs, gateway+native dispatch/alternate model paths, bootstrap-to-assets binding, stale/missing pin with unchanged business data, current valid calls, in-flight/poll mismatch, two tabs, native/custom dirty snapshots, session/actor change, explicit reload/cancel and no loop; actual core upgrade/fault/restore/new-epoch qualification remains required. Source-only tests do not pass UI07 or G5.
