# ADR 0011: independently staged images in the exact operation preimage

Date: 2026-10-28 (Asia/Riyadh).

Status: accepted for the G5 staged metadata/planning boundary. New-image execution and its fault/restore qualification remain in progress. Builds on ADR0008/0009; no frozen v1 envelope, valid fixture, public contract major or golden hash changes.

An approved new-image native operation must bind the immutable Docker image ID as well as its inventoried application/Python contents. Different image configurations or base-OS bytes can share the same application inventory. A mutable image tag, app metadata claim or unbound private pointer is insufficient.

An OS-authenticated local `plugin stage-image` observes the selected current deployment and candidate immutable image under the existing deployment-then-site process locks. Candidate inspection uses no live volumes/network and imports no plugin/native ORM code: it hashes the curated source inventory and static Python metadata, rejects missing/modified/unexpected addon files, and checks all packaged artifact identities against current independent catalog/trust. Match actual inventoried ZIP hashes and the exact mapped native addon files to the independently validated package inventory; an image self-inventory alone cannot bless substituted or extra native bytes. Building/acquiring candidate bytes remains a separate operator-controlled step; no command, URL or Docker descriptor comes from a browser/package nomination.

Persist an immutable candidate record under the protected control store, outside the app DB restore domain. It binds base configuration/generation/sites/policy, exact target image and runtime/inventory metadata. An independently selected active candidate pointer identifies the record; selecting another candidate invalidates pending plans referring to the old one. Approval/execution must reload the private record, verify its digest/base configuration and re-observe candidate image metadata. This does not claim to sandbox trusted native/core/image code or scan all OS content for safety; image identity pins the independently selected full image.

Add optional structured `staged_image` to the internal operation-lock preimage: stage-record digest, base/target image IDs, inventory digest and full runtime-metadata digest. The existing frozen plan's `dependency_lock_digest` authenticates that preimage transitively. Include the same descriptor in the derived full CLI review/download display. A rehashed app-forged image descriptor is rejected against the private candidate. Current-image/feature plans without this descriptor retain their existing bytes/meaning. The app remains an untrusted proposer, and the exact OS approval still governs one operation/hash.

Target planning combines the actual current site/workspace/installation state with the independently staged environment/provenance/Python metadata and exact packaged artifact roots. Enumerate changed/transitive/sharing targets, retain stable site installation IDs and existing compatible bindings, and bind concrete new workspace provider scopes before hashing. A packaged dependency is not implicitly DB-installed or activated. Unknown scopes, omitted required workspace dependencies, wrong image/runtime inventories and different independent recomputation fail before mutation. Staging must not change the current executable/DB state.

New-image execution must explicitly select this staged image for maintenance and replacement workers, retain the prior runtime/config/checkpoint and validate exact DB metadata, source inventory and release/client generation before opening traffic. Until that adapter and fault handling are complete, the current-image executor rejects any staged descriptor **before reservation or mutation**, even if a valid private approval exists. Read/plan/approve qualification is not a G5 exit or proof of native upgrade/rollback.

Public install/upgrade nominations remain exact plugin/site/workspace/version/digest proposals. Full browser preparation/status for staged releases remains a later G5 integration check; do not represent successful local staged planning as completion of that user flow. ADR0010 still governs frontend reuse: no root rewrite or parallel generic UI infrastructure is introduced here. Existing frozen public plan/host/service semantics and independent approval boundary remain intact.
