# ADR0028: reconcile current native authentication privately during restore

Date: 2026-10-29. Status: accepted and qualified through the clean G5 rehearsal. Extends ADR0012/0025. No public API/schema/freeze or native authentication implementation changes.

The OPS-02 clean rehearsal demonstrated that clearing an existing native password leaves the old canonical recovery authority snapshot unchanged. Principal/membership/operator state alone cannot prevent an older checkpoint from resurrecting a revoked password, TOTP secret, passkey or native group assignment. The transaction probe was rolled back and touched only the new disposable environment; original observations are retained.

Read current principal authority and native authentication from one repeatable-read/read-only database snapshot through the independent operator. Bind only a canonical digest and `r1-current-native-auth-v1` policy in the private recovery review. Keep password hashes and TOTP secrets out of review/status output: raw credential material stays in captured operator memory and fixed SQL stdin. After worker drain, re-read and compare the complete bound authority, then overlay current native passwords, active flags, TOTP secrets/counters, explicit native group assignments and current passkey rows in the restored database transaction. Preserve native Odoo credential formats/verification. Clear all remembered TOTP devices along with session rotation and technical credential revocation; remembered-device material must not reappear from the checkpoint.

The profile requires the same native user ID/login footprint and available group identities. Unexpected account/schema footprints require explicit reconciliation before traffic, rather than inventing or enabling identities absent from the checkpoint. Existing reference workflow stops ordinary app writes during maintenance. API-key/job/outbox/external runtime exclusions remain unchanged and G6 must extend/requalify those boundaries. Arbitrary trusted native authentication extensions are not inferred from grant metadata.

Verified restore results record the reconciliation policy/digest. Old pending results lacking that proof cannot resume under new host code. New resume reviews also bind the current native credential digest through the final post-readiness check, so password/passkey changes invalidate an earlier review. Completed historical operation status is retained; no existing operation or protected deployment is replayed. Existing public frozen contracts remain compatible; old private recovery decisions require a fresh review.

Changed consumers: host RestoreExecutor, its private result/review data and the local CLI; no application image/authentication/CRUD/Canvas rewrite. Native SQL queries use fixed identifiers and typed JSON records. Diagnostics remain private and maintenance children retain the no-daemon-log rule in ADR0027. MIG-06 is requalified by the actual populated clean restore and separately reviewed resume. Existing dispatch tests plus native credential tests cover ordering, malformed/private input, digest changes, legacy-result refusal and final traffic fencing; The actual source/restored private native snapshots match exactly for passwords/TOTP/counters/groups/passkeys; remembered devices are absent, old sessions fail, the new Alice password succeeds and her old password fails through HTTP. This verifies recovery of native MFA state, not a new WebAuthn authenticator implementation.
