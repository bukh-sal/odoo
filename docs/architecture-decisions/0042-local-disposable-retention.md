# ADR0042: retire closed local test fixtures with protected data archives

Date: 2026-11-02. Status: qualified bounded local operator practice; actual current runtime/data preserved. Parent G-01d0 and the user's explicit Docker cleanup instruction.

G0–G6 are qualified and the current consolidated R1 fixture is native27/126. Older stopped test environments are no longer active implementation targets. The read-only ownership audit binds projects to repository state/target records and image builds to local Git provenance. A name prefix alone does not establish ownership. Unmatched assets, including unrelated Arcadia work, stay untouched. The first bounded retirement archives diagnostics and removes105 exact exited owned containers without force or any volume deletion; all current data and volume names remain intact.

Before retiring an unused old fixture volume, require concrete former mount/project ownership, no remaining container users anywhere in Docker, and a complete protected cold archive. Record source Docker metadata, root UID/GID and the original database image where relevant. Read through an isolated, network-free operator helper; the mixed-UID configuration/database files require operator root with only DAC_OVERRIDE, while both the image filesystem and source volume are read-only and no Docker socket or host directory is mounted. This is a trusted backup operator, not the application or external worker identity. Never mount the archive or old credentials into the running application. Stream a private tar.gz, verify every regular file against pre/post content hashes and record archive integrity plus ordinary ownership/mode/link metadata. Recheck global volume users immediately before unforced exact-name removal. If ownership, access, archive verification or sharing is uncertain, retain the volume and continue independent safe work. Cold byte verification is not a claim that a database restore was rehearsed.

Preserve the current project's volumes, failed/recovery databases within its PostgreSQL storage, current app/edge/database/worker, independent authority, actual latest native checkpoint and its image, current/previous approved worker image and every currently used resource. Retire only obsolete repository-recorded images with no container users, no protected role and no unrelated tags. Preserve private source/inspection/build records; use no force or parent-image pruning. Historical closed fixture records remain evidence and data archives, rather than instructions to replay old approvals or completed operations. Current release restore qualification still follows the ordinary independently reviewed path.

Do not use global Docker prune, remove unknown databases/volumes, touch unrelated assets, retry the known hung Created worker/rejected core11 deletion, or retry the separately rejected browser-profile filesystem deletion. Shared BuildKit cache is outside an ownership-based removal plan until exclusive ownership can be established. Do not claim progress for this documentation or qualify G7 merely by cleaning assets.

Qualification: ../evidence/G7/20261102-docker-retention-01/qualification.json. Exact105 exited containers,61 unused volumes and28 recorded unused images retired. All volume contents and ordinary metadata were verified in protected cold archives (2.289GB source,495.9MB compressed), rehashed and fsynced after retirement. Current/recovery/worker and every unselected asset remain. Global shared BuildKit cache and unmatched resources were deliberately outside the ownership-bound selection. Full G7 remains open.
