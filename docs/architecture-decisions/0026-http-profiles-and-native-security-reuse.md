# ADR0026: explicit edge profiles while retaining native security

Date2026-10-29. Status: accepted and qualified for current local R1 topology under G5-X08/SEC02/04. No public contract or native ORM/session/view rewrite.

The previous catch-all development proxy accepts unknown Hosts and has no separate production HTTP profile. Preserve Odoo authentication, login cooldown, session storage/rotation, CSRF and native transports. Add a small fixed Nginx profile renderer, not an alternative authentication subsystem. Development permits loopback/localhost subdomains; production requires one canonical HTTPS origin, validated as data before rendering. Unknown authorities and foreign/null Origins fail closed. Empty Origin remains allowed for nonbrowser clients; native/gateway mutation checks still apply.

One direct edge is the trusted proxy. It overwrites forwarded host/proto/address, drops other forwarding claims, and owns shared per-client public/service/operator/login limits. Native login cooldown remains an additional control. Application and DB have no published ports; application proxy_mode is explicitly enabled only with that topology. All application-network code remains trusted. No arbitrary forwarded chain or general proxy-CIDR framework is introduced.

Edge tightens native session flags to host-only/HttpOnly/SameSite=Lax, plus Secure under HTTPS. It does not replace tokens/expiry/CSRF semantics. Production terminates operator-provided TLS1.2/1.3, redirects HTTP to the fixed canonical origin, blocks database-management/listing and native developer/test/debug paths, preserves ordinary native assets/views/RPC and the bounded100MiB upload exception. Logs omit query strings/bodies/credentials; rate-denial access statuses remain visible. Production initialization, sample-user disabling and credential rotation remain explicit operator operations, with preflight and actual qualification required.

Only new owned disposable fixtures may activate these profiles during qualification. Existing main/manager/lifecycle/dispatch deployments retain their recorded proxy bytes until separately authorized operator rollout; changing a repository template does not mutate them. Verify allowed and denied HTTP/TLS/authenticated-CSRF/CORS/host/proxy/cookie/rate/native-view cases, code/config/data preservation and production credential/dev defaults before passing. Native Python and same-origin plugins remain fully trusted. Canvas remains minimal.

Qualification: [http-security-02](../evidence/G5/20261029-http-security-02/qualification.json). Preserve platformAPI429/frozen DTO separately from native Odoo UserError/data error handling; actual pinned native parser/handler checked. Existing4deployments unchanged. Full release secret scanning and independent authority/OS isolation remain open.
