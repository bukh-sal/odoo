# ADR0031: durable scoped event delivery with native bus wakeups

Date: 2026-10-29. Status: contract design; G2 revision13 must pass before runtime consumers. Parent item F-01b2; specification11.6,13.5,14.1,17.4,25.3. Builds on ADR0029/0030. Previous goal turn PROGRESS: F-01b1 qualified/committed133e5dd8; current worktree clean on resumption. No current test or mutation is pending.

The existing host event facade only stores callbacks. Reuse the installed native Odoo bus for payload-free wakeups, and native transaction hooks for their commit boundary. Bus message IDs and transient retention cannot supply durable domain delivery. Keep the native outbox; do not introduce a broker or replace the WebClient/native CRUD integration. Periodic scoped fetch remains the correctness path if a wakeup is lost or websocket transport is unavailable.

Add one authenticated, CSRF-protected same-origin POST `/api/v1/events` with strict versioned subscribe/poll/ack/status/replay/close DTOs. Use existing release/workspace headers and a current declared service binding on subscription creation. Binding IDs and subscription IDs are routing references, never authority. Derive actor/site/workspace/consumer/provider from current native metadata. The reference topic is `org.example.notes.changed`, authorized through the current Notes documents read binding (major1 or2), plugin/feature/grants, original backing user and any intersected technical credential. Recheck authority on every fetch, acknowledgement, status and replay; return no foreign subscription/event payload.

Subscriptions belong to one actor/workspace/consumer/binding/topic and expire after one hour. Same create idempotency key and input join the same subscription; changed routing/input conflicts. Correlation request IDs confer no authority or replay permission. Browser mount generation changes close/abort the old subscription and stop callbacks. Preserve the existing UI-major1 `HostEvent {id,topic,data,generation}` shape; map a validated wire envelope to it, with generation derived from the current mount. No serialized role, actor or workspace overrides are accepted by the request DTOs.

An envelope contains immutable event ID/topic/schema version, owner plugin, aggregate ID/optional sequence, site/workspace, occurrence time, correlation/causation and bounded validated minimized payload. Reference Notes create/update/delete (including cooperative Labels writes) produce only note ID, revision and change kind, never title/body/labels. Insert the outbox in the same native transaction; rollback yields no delivery. Native bus messages contain only a constant wakeup marker and use existing user-partner channels; they carry no domain payload, scope, aggregate identity or authority. A wakeup always triggers a separately authorized fetch.

Delivery is at least once with no global ordering. Select eligible committed outbox rows by a per-subscription receipt anti-join, not an allocated-ID high-water mark. Concurrent transactions may allocate IDs and commit in reverse order. Native Notes revisions provide aggregate sequence information, but the transport does not promise receipt order. Seven days of occurrence-time history is eligible for retained replay; a transaction first visible outside that explicit window is expired, never evidence of a skipped in-window commit. Subscription/delivery state logically expires; physical test/history rows remain retained until an explicit retention/erasure operation. Do not silently delete user data to bound a test.

Each delivery has its own opaque receipt/generation,15-second acknowledgement lease, at most five attempts and retry delay1,2,4,8…seconds capped60. Unacknowledged expiry can redeliver. Completion acknowledgement is idempotent for the same current receipt, but an obsolete replacement receipt cannot acknowledge a newer attempt. Dead-letter status exposes bounded IDs/attempts/fixed codes to the current owner, never exception values. Explicit replay is limited to50 retained authorized events and three replays per receipt record; it resets delivery attempts, not consumer deduplication. Expired payload replay is refused. Closing/expiry/revocation stops new delivery; an earlier committed producer is never rolled back by consumer failure.

The reference native consumer is a small Labels-owned revision/count projection, without new product UI. Its registered handler runs as the current original actor and needs current Labels write authority in addition to the bound Notes read grant. A unique consumption receipt keyed by consumer installation/workspace/handler/event ID commits with the native projection effect. Repeated delivery or a new subscription cannot duplicate that effect. Retry callback failure rolls back consumer acknowledgement/effect only. The browser facade additionally deduplicates within its live mount and acknowledges after all current callbacks return; callbacks remain responsible for durable external effects. No exactly-once external-effect promise is introduced.

Freeze the additive schema, positive/negative fixtures, protocol and exported wire types before implementing native/browser consumers. Existing DTOs, service majors, host facade shape, plan golden and token contracts remain compatible. G5 historical evidence remains unchanged; new runtime/package versions still need source-bound native/HTTP/browser qualification. JOB-01/02 remain qualified on their retained source boundary; events add no acceptance credit until actual rollback/out-of-order/duplicate/revocation evidence passes.

Revisit if a durable broker, new event contract major, ordering guarantee or different retention policy is actually required. R2 confinement, an event-driven rewrite, additional Canvas features and UI polish are outside this item. Actual populated-queue upgrade/restore support remains required in F-01e; do not bypass its current explicit rejection to deploy this feature.
