# ADR 0023: native database uninstall and separate artifact removal

Date: 2026-10-29. Status: partial implementation for G5-X05. Additive G2rev12 contract and verified-source/read-only impact inspection qualified; independent exact operation binding is source-qualified. Fixed native child/tombstone publisher are implemented_unverified; runtime endpoint/reinstall/removal/activation and destructive qualification remain pending. No acceptance credit. Builds on ADR0008/0011/0012/0013; native Python remains fully trusted. Standard CRUD remains native Odoo; Canvas remains a minimal fixture.

The existing pure planner recognizes uninstall/remove, but neither the current-image nor staged executor implements them. At design time pure uninstall preserved the entire old release lock, although removing bindings and native schema changes observable state and must retire old clients. Reusing that assumption in execution would produce a false published preimage or leave an old client generation active. Existing planning tests are not native uninstall evidence.

Use the existing NativeExecutor approval/reservation, deployment-then-site locks, drain, checkpoint, fixed maintenance child, metadata publication, guarded worker replacement, assets/readiness and journal. Native uninstall normally retains the exact current image/package bytes. It needs a new generation/timestamp and service selections reconstructed from surviving bindings, with unchanged code/Python/core/plugin identities. Do not require a new image merely to call upstream uninstall. Reject rehashed proposals that change any executable identity, omit affected workspaces/dependents or reuse the old generation. Pending approvals bind the full new preimage and require ordinary independent reconstruction; do not alter approved operations in place.

Native uninstall is site/database-wide. Determine the installed native dependent closure from actual metadata and the pinned native manifests; require consistency with the native dependency graph before mutation. Include every affected workspace and required service consumer, including suspended scopes. Unsupported non-package/core dependents block this path rather than being silently removed. A fixed controlled native child loads only the independently selected current image/database, compares upstream's actual downstream closure with the approved module set, and delegates to upstream button_immediate_uninstall. No caller supplies Python, SQL, paths or shell text. Native commits make failures/uncertain process outcomes recovery_required; never infer rollback or replay from a lost observation.

Before approval show the exact known model/field ownership, SQL relations/constraints, record counts, assets, jobs and foreign references. Use bounded read-only data inspection and exact verified source declarations; do not import plugins during planning or guess a custom model-to-table mapping. Mark unknown mappings/effects honestly and retain the warning that arbitrary trusted hooks may have additional effects. The actual native child records before/after schema/data effects and validates surviving installed modules and supported interfaces. Counts/schema effects belong in an internal hashed impact preimage, not untrusted browser-selected commands. No job/outbox tables are currently supported: keep the existing fail-closed rule until G6 provides drain/reconciliation.

The frozen operations request already reserves site-wide uninstall/remove nominations. Preserve its shape and existing plan/approval/host formats. Add a separate strict read-only lifecycle-impact DTO/endpoint bound to operation ID and plan hash, rather than silently extending the strict prepared view. Record schema/examples, consumers and compatibility in G2 revision12 before runtime implementation. Reuse the Operations preview/status/CLI instructions, adding only required impact/destructive confirmation and recovery wording; the web application still cannot approve or execute privileged work.

Retain stable installation/scope tombstones after native uninstall with database state not_installed and feature suspension; remove affected live bindings and revoke scoped integration grants. Native schema/data deletion and package removal remain distinct. Projection, manager dimensions, readiness and a later reinstall must handle tombstones without claiming imports were unloaded. Reinstallation must initialize the current version, preserve stable identities, explicitly renew requested grants, and avoid replaying historical upgrade scripts. Replace workers even when the image is unchanged.

Artifact removal is a later separately approved staged image change. Reject it while any observed sharing database still requires the package, while a native module is installed/pending or while another package requires it. Do not delete catalog archives, previous images, checkpoints or old files as a side effect. Accept only the exact inventoried removal of the target package/addon from an operator-built image, preserving all unrelated core/Python/source policy. Keep removed metadata honest and do not look up an absent runtime descriptor as if the package were still present. No general marketplace/runtime builder is introduced.

Required qualification: retained suspension schema/data/native field behavior and scoped dependency closure; permission expansion/reapproval; omitted native/service dependents and partial workspace rejection; destructive acknowledgement and valid checkpoint; actual upstream uninstall with observed SQL effects and surviving Notes/Canvas APIs/native views; artifact-in-use rejection and exact subsequent image removal; reinstall using stable identities/current schema/no simulated upgrades; unknown outcomes through the existing journal/recovery boundary. Use only the new lifecycle fixture, never uninstall main28 or retained manager6. G5-X06/X09 still own full process-crash/concurrency/clean restore proof.
