| Work on a record | Page header with title, current record/breadcrumb and one contextual primary action; list/form/board beneath | Preserve native model/renderer, paging and edit behavior. ## UI-D03 implementation plan

1. **Trace a real route before changing chrome.** Start at `framework_addons/web/static/src/webclient/webclient.{js,xml}`, `navbar/`, `menus/menu_service.js`, `actions/action_service.js`, `search/control_panel/control_panel.xml`, and `mp_core/workspace_landing.py` / `static/src/workspace_menu.js`. Map sign-in without workspace, workspace with no app, Partners root/record, Workboard task/reminder and Documents detail. Trace browser back, direct load, default app, current menu and fullscreen. Record which layer supplies the destination, scoped visibility, action, selected key, history and leave hook. Inspect the current `/web/webclient/load_menus` producer and real scoped responses before assuming any menu represents workspace authority.
2. **Resolve the source of visible navigation.** `getApps()` enumerates root menu children; `selectMenu()` delegates to the action service. The existing `/api/v1/navigation` route lives in optional `mp_shell/controllers.py`; it reads enabled installations after a scope check. Core's `/api/v1/context` already resolves one plugin's current context/capabilities. Trace page permission and native action/menu resolution in addition to feature visibility. Prefer extracting/reusing the existing scoped projection in `mp_core`, with the web presentation consuming it through a small neutral provider. Preserve optional-shell clients, response contracts and bare-web startup. Verify existing route ownership before moving it; one effective route handler. Filter destinations by stable plugin/page/action identities, mapped to currently accessible native actions. Unknown, suspended and unresolved entries stay out. Keep failure/unavailable distinct from a genuinely empty workspace. No global catalogue or cross-workspace fallback when this read fails. If a supported contract must change, record the affected consumers, ADR, freeze and tests first.
3. **Build the shell once.** Compose the rail, workspace/account area, contextual region and action canvas in the existing Owl WebClient. Keep one `ActionContainer` and one `MainComponentsContainer`; preserve dialogs, notifications, fullscreen actions and focus. Replace the horizontal app section presentation, including its inherited purple backgrounds. Retain the useful menu/action execution and systray contributions. Reconcile navbar/mobile breadcrumb portals with the new mount before retiring old markup. Use live translated labels and icons, logical CSS properties, focus-visible styles, an accessible current destination, keyboard-operable All apps, and existing `command.openMainPalette`. A keyboard or pointer user must be able to discover every destination. Leave persistent pinning out of this slice.
4. **Integrate the first real apps in the same slice.** Inspect the private Workboard `static/src/navigation.js`, task/reminder pages, Delivery's Customer work view and Documents library. Delivery imports `WorkNavigation`; keep its navigation and task-panel contributions functional through the transition. Reuse existing native action refs and scoped routes. Scope any contextual Owl slot/component to the active action and tear it down on navigation; dynamically loaded lists must not leak into the next app or workspace. For the first implementation, let a custom action render an app-owned context pane inside the shared layout if it already owns its list state. Keep a single visible pane. Support native, standard custom, tokens-only and immersive pages without loading a private app into core. Remove redundant link strips only after equivalent destinations work, including when an optional companion is absent.
5. **Protect working behavior.** Preserve validated workspace/deep-link parameters and back/forward/reload. Route app changes through the existing action/leave lifecycle; cover dirty native form, edited task and uncertain request, including cancellation. Keep contextual New, normal record links and the search/filter count. Scope changes, release changes and stale responses must discard old navigation/results; never copy drafts into URLs or browser persistence. Preserve server authorization for a manually entered URL, RPC, file bytes and actions. Document any genuine unsupported transition and its reason.
6. **Deliver an installed comparison.** Make separate local source commits in the platform and the affected private repos. Give changed packages new versions/digests and appropriate minimum platform bounds. Compile selected assets early with the pinned toolchain. Use normal candidate build, bootstrap, catalog, stage, plan/review/exact approval/apply on a fresh, named disposable development site. Verify existing protected targets and choose free port/subnets at execution time. Retain private business fixtures and screenshots locally. Capture the same task list and native record at matched viewport, theme and data; compare to the prior installed UI and Meridian. Ask for a visual judgment with paired screenshots only when a consequential choice remains, such as narrow navigation taking the whole screen versus overlaying the canvas.

### D03 acceptance card

- **Zero, one, many.** Bare core with no workspace offers the existing chooser/empty state; an active empty workspace retains own-jobs/account access. One-app and overflow cases expose actual destinations. Viewer A/B differences, suspension/removal, reload and revoked membership are checked against the server. No made-up app or private business name/count appears after denial.
- **One home per navigation level.** Workboard has one active app identity and a single My reminders destination in its normal chrome. Partners retains People/Organizations; Documents has one library pane; Customer work remains reachable with Delivery installed. Exercise rail, All apps, global palette, page search, direct record URL, modified-click/open in new tab and browser Back. Confirm the expected route, title, selection and workspace after each.
- **Readable and operable.** Test 1280 px desktop and 390 px narrow, plus long translated names, an RTL smoke check, keyboard-only open/close/return focus, and filtered list restoration. Inspect collapsed/expanded overlays, outside dismissal, scroll and focus order. One overlay at a time. Maintain the accepted desktop width; allow wrapping. Save screenshots of both native and custom views.
- **No silent state loss.** Cancelling a leave leaves form/task draft and focus intact. Existing workspace switching opens a scoped tab. Verify viewer write refusal, foreign-record denial, empty vs unavailable, and the familiar Workboard 24 → 5 → 24 filter path on equivalent seeded data.

Start tests near the edit: native `navbar.test.js`, `menu_service.test.js`, `command_palette.test.js`, the stock workspace menu checks, and private navigation/controller tests. Add only missing regression cases. Mocks prove selection logic; browser checks prove rendered composition, focus, permissions and transitions. Record failures and their disposition.

## Later-phase execution briefs

**D04 — Make the upgrade real.** The runtime receipt reports raw web manifest version `1.1`; inspect the installed native module version separately. In `packages/platform_sdk/modular_platform/release_staging.py`, `CORE_ADDONS` excludes `web`, and `validate_core_upgrade` requires strictly increasing canonical versions for touched core addons. Simply bumping `mp_core` or rebadging the old image cannot qualify this transition. Reproduce the exact refusal using the two observed inventories first. Design the smallest owned-web maintenance rule for the reviewed source range and the known legacy-to-canonical version transition. Bind historical manifest and file identities, target manifests, exact deltas, base/target inventory and stored approval; admit future versions through normal monotonic comparisons. Reject unexpected backend/executable files, other upstream addon or app drift, stale base, forged source and mutated evidence. Check both the planner and independent validator/native executor. Evaluate freeze impact before edits. Keep platform-only maintenance and private app upgrades separate wherever release rules require identical app pins. Exercise checkpoint/rollback or restore via the supported isolated workflow. Compare business IDs/revisions, document bytes, grants, memberships, scoped dispatch and current release; reopen traffic through normal review. A fresh install is sufficient to review D03 visuals, but D04 requires a populated predecessor. Preserve the control on 18608 and historical images. If the source guard refuses, record and resolve the exact limitation before any new operation.

**D05 - Make the applications feel like one product.** The [current-source implementation plan](ui-work-surfaces-plan.md) was activated after installed legacy maintenance/recovery qualification. Use the real journey: open a customer in native Partners, find related work where the installed companion provides that route, narrow the task list, open a task, follow its pinned brief, view the current and pinned versions in Documents, then return to task context. Map any genuine missing link; either implement it in its owning optional app or give the user a clear supported route. Include one edit with save/cancel, stale revision and viewer denial. Derive shared page/header, record section, contextual sheet and feedback patterns from these screens. Use existing field renderers, dialogs and focus restoration. Keep one primary action, distinct loading/empty/filtered-empty/error states and truthful save status. Catalogue the patterns with actual usage snippets, states, localization, scope and fallback. Prove reuse on native Partners and two independent custom apps. Keep business labels, counts, permissions and specialized layouts app-owned.

**D06 — Qualify the integrated experience.** Use matched light/dark desk and narrow captures, real Arabic locale/RTL and mixed identifiers, long destinations, keyboard-only journeys, visible focus, 200% zoom, contrast measurements and reduced motion. Inspect popup positioning, sidebar overflow, sheet focus/scroll, native and custom unsaved transitions. Compile selected bundles and RTL assets, validate archives/identities, run affected security and app tests and the canonical host runner for the integrated candidate using its documented isolated environment. Distinguish measured checks from formal accessibility or broad platform-support claims. Verify optional-app install/disable/removal on owned fixtures, stale-link behavior and current access after a scope change. Deliver an app-free boot and a populated review site, local commits, an installed walkthrough, before/after captures, open limitations with reasons/owners, and exact retained resources or scoped cleanup receipts.
