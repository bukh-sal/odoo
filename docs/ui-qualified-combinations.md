## Intentional limits and their reasons

* Native Python and same-origin frontend apps are trusted code. Workspace gates,
  independent operator approval and scoped technical identities protect supported
  paths; grant metadata is not a native-code or frontend sandbox.
* Shared components provide presentation, not business models, authorization or
  draft persistence. Apps own those behaviors through normal APIs/controllers.
  Components importing the new exports declare core>=0.2.12. Native renderers
  and shared token/class styles remain available without those imports.
* Native code is shipped through immutable reviewed images. A suspended feature
  does not unload code; database uninstall and source subtraction are distinct
  operations. Source removal rejects unrelated distribution-policy changes,
  including a changed profile/omitted package-list key. Use the existing clean
  removal builder or an exactly subtracted policy; do not relax the guard.
* No chat, global business-record search, persistent pin-management service or
  other concept-only control is implied. Those need real owned workflows and
  authorization contracts before presentation. This is scope, not evidence that
  the platform forbids building such applications.
* Existing core/vendor notices, the Partners test package's LGPL-3.0-only label
  and private independent application boundaries remain unchanged.
