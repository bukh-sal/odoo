# Provisional core 0.2.1 qualification

This is local candidate qualification. It does not publish an application or
authorize production deployment, a stable ABI, long-term support or compatibility
with arbitrary addons. The owner selected the eight-addon default and the
[candidate support boundary](../../../candidate-support.md).

| Roadmap requirement | Demonstrated result | Evidence scope |
| --- | --- | --- |

The canonical runtime-source host regression ran 810 cases: 808 passed and two
existing platform skips, with no failures/errors and 4,810 monitored inputs
unchanged. A later host-only default-policy change has its own 32 passing
targeted checks. These are separate provenance claims rather than a full-suite
claim on every later documentation commit. Frozen-contract validation passed
119 files across ten rows.

An actual 0.2.0 reinstall exposed reuse of a retained idempotency receipt when a
binding was recreated at generation one. Core 0.2.1 allocates a new incarnation
from the release epoch. Its normal reinstall creates generation-ten bindings,
refuses the retained obsolete key with 409 and deduplicates a new key against a
real record. Receipt history is retained. Recovery then preserved three original
records and eleven event business rows, retained a newly revoked workspace,
and supported useful work after a separately reviewed resume.

The standalone core build has the same inventoried runtime source files as the
qualified subtraction image. Its locked Python dependencies were rebuilt, so
their binary fingerprints are not asserted byte-identical. The clean final
layers, exact materialization and a fresh core-only bootstrap/login/native
list/form/read/stock-WebClient HTTP smoke were independently checked. The
private smoke wrapper initially omitted empty catalog initialization; its
failure trace and initialization results were preserved, and only publication
continued after exact state reconciliation. A subsequent import-only private
checker failure is also retained. No initialization or operation was replayed.

Raw credentials, authority snapshots, synthetic contact contents and detailed
checkpoint/restore records remain private. The adjacent sanitized receipts bind
their hashes and report scoped outcomes. Historical sealed releases and earlier
failure evidence remain unchanged. Tasks, Storage, Documents, complex migrations,
arbitrary external workers and broad application compatibility are outside this
candidate's qualification.
