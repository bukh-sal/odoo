# R1 HTTP profiles and operator preflight

Use the existing Odoo authentication, session rotation, login cooldown, CSRF and native list/form transports. The edge adds perimeter policy; it does not grant installation authority or contain trusted native/same-origin plugin code. [ADR0026](architecture-decisions/0026-http-profiles-and-native-security-reuse.md) records the decision. [Current local qualification](evidence/G5/20261029-http-security-02/qualification.json) is not an external production deployment.

## Development

`deploy/nginx-r0.conf` is generated by `tools/http_profile.py`. It permits localhost,127.0.0.1,loopbackIPv6 and `.localhost` subdomains, retaining URLs such as g5.localhost with arbitrary local test ports. Unknown Hosts get421. Requests with an Origin must match their actual scheme/authority/port; foreign and `null` Origins get403, with no credentialed cross-origin sharing. Missing Origin remains supported for CLI/native clients; application CSRF and actor/workspace checks still apply.

Session cookies are host-only/HttpOnly/SameSite=Lax. Local HTTP uses no Secure flag; production HTTPS requires it. Browser cookie scopes do not separate ports: use separate localhost subdomains for distinct browser sites. Generate a new file, inspect it, and use a separately reviewed operator config-volume update plus `nginx -t` before reload. Rendering never overwrites an existing file or mutates a running target.

```powershell
.venv/Scripts/python.exe tools/http_profile.py --mode development --output .local/new-development.conf
```

## Production profile

The qualified topology has one direct TLS edge, an internal-only application and PostgreSQL network, no published app/DB ports and one canonical HTTPS origin. Only the direct edge supplies forwarded host/proto/client address; it overwrites incoming values and clears other forwarding claims. Do not put an unconfigured forwarding chain ahead of it or add untrusted containers to its internal network. The app's `proxy_mode=True` is safe only with that topology. External service/worker topology must be separately qualified when introduced in G6.

Before opening ingress, the OS operator must explicitly initialize the selected site through the approved lifecycle/bootstrap path, provision named human accounts, disable the initial `admin` and shipped `g1_`/`r0_`/`r1_`/`g5_` fixture logins, rotate bootstrap/session credentials and revoke obsolete technical credentials. Never use fixture seeders or documented shared credentials for production. Set `web.base.url` to the canonical HTTPS origin and `web.base.url.freeze=True` through an authorized operator operation. The profile does not silently initialize a database, migrate schemas, create users, change passwords or erase data.

The private native config must select one database with an exact anchored filter, `list_db=False`, `proxy_mode=True`, no dev/test flags and `log_handler=:INFO,werkzeug:ERROR` (or a stricter Werkzeug level). Worker startup retains its existing independent immutable inventory/database pins, curated addon paths, pending-native-state checks and cron0. Keep the selected immutable image; the production Compose override removes inherited build instructions.

For example, after setting the independently selected paths/image/origin:

```powershell
.venv/Scripts/python.exe tools/http_profile.py --mode production --origin $publicOrigin --odoo-config $privateNativeConfig --image $approvedImageId --output $newProxyConfig
.venv/Scripts/python.exe tools/production_preflight.py --deployment-config $deploymentTarget --odoo-config $privateNativeConfig --origin $publicOrigin
```

The read-only preflight verifies actual selected runtime/config, publication, inactive shipped users, absent development modules, frozen canonical URL, nonroot/read-only application and internal-only networking. It is the qualified local R1 Docker adapter; it neither approves an executor operation nor supports arbitrary remote production targets. A failed check requires reconciliation before opening ingress. Native installation/upgrade/recovery still requires its separate exact-hash independent executor approval.

Use operator-issued TLS material outside Git. Mount `server.crt` and `server.key` read-only at `/etc/mp-tls`; certificate is readable by the edge and private key only by UID101 (mode0400). Keep the private key outside application mounts and the database/filestore backup domain. Set permissions **before** changing ownership. `/run` is unsuitable here because the stock image's `/var/run` symlink/tmpfs can hide a nested TLS mount. Local tests generate a two-day certificate and explicitly trust it only in the test client; they do not install workstation trust or prove public certificate issuance/renewal.

`deploy/compose-production.yaml` overlays the base Compose profile. Set `MP_IMAGE` to the exact approved sha256 image, `MP_EXPECTED_DATABASE`/`MP_EXPECTED_INVENTORY_DIGEST` independently, and provision private `appconfig`, generated `proxyconfig`, and `tls` volumes. Set `MP_HTTPS_PORT` and origin consistently. Only loopback is published by default; changing `MP_BIND_ADDRESS` is an explicit operator deployment decision and is not authorized by the current local implementation goal. Inspect resolved Compose configuration and run `nginx -t` before opening its edge. Initialization/maintenance stays a separate explicit operator operation.

HTTPS allows TLS1.2/1.3 and host-only Secure/HttpOnly/SameSite=Lax sessions, with HSTS and no broad parent-domain cookie. HTTP redirects safe reads to the fixed canonical HTTPS origin and rejects mutations. Unknown authorities are rejected rather than used in redirects. `/web/database*`, developer/test/tour/debug asset paths and nonempty `debug` query switches are denied. Ordinary Odoo assets, native RPC/list/form views and trusted optional plugin custom pages remain available. Excluded external RPC transports stay absent from the curated image.

## Limits and errors

Shared edge limits key the actual socket client address, never untrusted forwarded addresses. Native login cooldown remains additional protection; no replacement password/authentication implementation exists.

| Category | Rate | Burst |
| --- | --- | --- |
| General public/dynamic paths |50requests/second|100|
| Registered service calls |20requests/second|40|
| Operator prepare/request/upload |5requests/second|10|
| Production login pages/authentication |5requests/minute|10|
| Development login pages/authentication |10requests/second|30|

Locations with a dedicated limit use that category instead of the general limit. The native manager additionally enforces its per-actor preparation limit. The100MiB upload exception stays restricted to its exact validation endpoint; other requests retain10MiB and service payload schemas retain their smaller bounds. Rates are initial R1 defaults, not a final G7 throughput claim.

Edge429 has Retry-After12 and no-store. `/api/v1/*` receives the existing frozen `RATE_LIMITED` DTO with a canonical request UUID, retryabletrue and `outcome=not_started`: the upstream action was never dispatched. Other paths receive Odoo's native JSON-RPC UserError/data envelope so its existing parser/dialog machinery remains usable. No custom dialog implementation is added. Access logs include address/method/path/status/bytes and omit query strings/bodies; strict edge error logging and disabled Werkzeug access INFO prevent the tested query/body canaries from appearing in logs. Full artifact/secret release scanning remains SEC03.

Existing running config volumes are not changed by editing templates. The qualification creates a separate owned project; main28,manager6,lifecycle18 and dispatch20 retain their previous bytes/state. Do not mutate those deployments or treat source qualification as permission to deploy externally.
