# Domain-event transport major1

Normative additive contract under ADR0031/spec14.1. Its schema is `packages/contracts/v1/event-transport.schema.json`; examples and semantic/negative fixtures are in the same contract inventory. Runtime qualification is separate from G2.

Use authenticated same-origin `POST /api/v1/events`, JSON, existing CSRF/workspace/client-release headers and the ordinary safe service response/error envelope. `data` contains one event-transport message with integer protocol1 and a discriminating kind. Requests are subscribe/poll/ack/status/replay/close; each includes a correlation-only request_id. Subscription creation additionally supplies a UUID idempotency_key and topic, with the existing X-MP-Binding header. The native server derives the actor/site/workspace/consumer/provider and current topic permission. No request can override identity, role, site/workspace, provider, grants or release. Opaque IDs/receipts do not authenticate a caller.

One subscription belongs to one actor/workspace/consumer/binding/topic, expires one hour after creation and revalidates current original-user authority on every operation. Same create key/input joins the same subscription; changed input/binding conflicts, and an expired/closed subscription requires a new intentional key. Initial delivery includes eligible retained events. No allocated event-ID cursor is accepted or returned. Selection uses committed outbox rows and per-subscription receipts so a later-committing, lower-ID transaction is not skipped. No global or transport receipt order is promised.

An event has immutable id, topic, payload schema_version, owning plugin, aggregate ID/optional sequence, site/workspace, UTC occurrence time, correlation/optional causation and minimized registered-schema payload. Unknown topics cannot be subscribed to merely because their shape is valid. The Notes reference topic's payload is exactly note_id/revision/change; owner is org.example.notes, schema1, aggregate ID equals note_id, aggregate sequence equals revision. Changes are created/updated/deleted; deletion uses the last Note revision plus one. No title, body, labels, exception, credential or serialized permission is emitted. Cooperative Labels changes use the base Note mutation/revision and produce one event in the same transaction.

Messages are at most64KiB of RFC8785 JSON, each event at most16KiB and depth at most16 (root depth1). JSON numbers must be finite and within the JavaScript safe numeric range. Arrays/objects and strings also obey schema bounds. Poll batches contain at most50 unique delivery/event IDs and may be smaller to satisfy byte bounds. Dates use valid UTC calendar timestamps, optional1..6 fractional digits and a final Z. Duplicate JSON keys, unknown keys, unsupported protocol or payload versions and terminal-newline identifiers are invalid.

Delivery is at least once. A delivery contains an opaque receipt, monotonically increasing generation, attempt1..5 and15-second acknowledgement lease. Acknowledgement carries delivery_id/receipt/generation; duplicate delivery IDs in one request are invalid. The same already-acknowledged current receipt is idempotent. An expired or replaced unacknowledged receipt conflicts; it cannot acknowledge a newer attempt. After an unacknowledged lease, retries wait1,2,4,8…seconds capped60; after five attempts the delivery is dead-lettered. Callback failure cannot roll back a committed producer operation.

Status exposes at most50 owner-authorized delivery IDs/event IDs, states, attempts, replay counts and fixed ACK_EXPIRED/CONSUMER_FAILED codes, with an explicit truncation flag. It never exposes raw errors or foreign subscription existence. Explicit replay accepts at most50 retained current-scope event IDs and three replays per delivery record, resets delivery attempts and replaces its receipt generation; it never clears native consumer deduplication. Repeated replay commands are new intentional attempts even with the same correlation ID; after an uncertain response inspect status rather than blindly repeating. Close is idempotent for a currently authorized owner and stops new delivery.

Retained replay is eligible for seven days from server occurrence time, including events whose allocating transaction commits after later IDs within that window. Events first visible outside that stated window are logically expired. Subscriptions expire after an hour; expired/closed subscriptions cannot poll or replay payload. Acknowledged/consumption tombstones remain at least as long as their event's replay eligibility. Logical expiry never authorizes deleting user data: R1 test/history rows are physically retained until an explicit operator retention/erasure procedure. Existing held/uncertain queues and failed releases must remain available for reconciliation.

Native consumption commits its unique installation/workspace/handler/event receipt with the original-user projection effect and acknowledgement. A late/obsolete lease rolls that consumer transaction back. Duplicate delivery, explicit replay or a new subscription cannot duplicate that effect. Browser callbacks receive the unchanged HostEvent id/topic/data/generation shape: data is the validated minimized payload and generation is the current mount, never a wire-supplied authority. Acknowledge only after all live callbacks return; maintain mount-local event dedup and stop delivery on abort/dispose/context change. Callbacks needing durable external effects still require their own idempotency/reconciliation. No exactly-once external-effect guarantee is made.

Reuse native Odoo bus user-partner channels for a constant wakeup marker only. No topic, payload, aggregate or workspace is carried on that channel. Always authorize the subsequent durable fetch; a missed wakeup, bus retention or max native bus ID cannot erase a domain event. Scoped periodic polling (default2seconds, response bound1..10seconds) remains the correctness path. Cached/pending browser delivery follows the existing maximum30-second authority lifetime and generation/visibility revalidation rules. Consumer/plugin/credential revocation blocks the next operation; saved outcomes and replay still require current authority. Native CRUD, custom layout, optional custom pages and Canvas's existing listener remain compatible.
