# R1 protocol major 1

This document plus the strict schemas, TypeScript types and examples in the freeze inventory is normative for R1. The specification remains the implementation requirement. G2 fixtures establish contract compatibility, not later runtime acceptance.

## Encoding, IDs and normalization

JSON Schema draft 2020-12, UTF-8, duplicate object keys rejected, explicit standard-library calendar validation for the UTC-Z date-time profile (including fractional seconds where the schema permits; no optional-format dependency). Server requests are bounded to 64 KiB before JSON decoding; method input/output schemas add tighter limits. No schema retrieval from the network at validation time. Unknown fields are rejected in every authority/manifest/plan/envelope object. Service `input` and response `data` must additionally validate against the selected registered method's schema. Manifest `extensions` accepts only reverse-DNS keys and cannot change authority or dependency behavior.

Public principal/site/workspace/installation/binding/object/operation/request/trace IDs are canonical lowercase UUID strings; native integer row IDs and database names never enter generic plugin APIs. Plugin IDs are lowercase reverse-DNS with at least three components. Contribution IDs are `plugin_id:kind:local_id`. Local aliases/page IDs use `[a-z][a-z0-9_]{0,63}`. Reserved plugin prefix `org.modularplatform.*`, exact core addon names `mp_compat`, `mp_identity`, `mp_core`, `mp_shell`, `mp_jobs`, and prefix `mp_core_*` are platform-owned. Examples use `org.example.*` and `mp_example_*`, reserved as repository fixtures. Other third-party `mp_*` names require a stable plugin-to-addon mapping and collision check; native names are never derived from a display name.

`normalize_manifest` fills empty dependencies/integrations/requests/provides/requires/pages/navigation/contributions/transitions, and page UI major 1. The resulting shape is `manifest.schema.json`; identity/compatibility/runtime/activation/upgrade declarations remain mandatory. Permission definitions normalize local keys to `plugin_id:local_permission`; requests and cross-plugin references must already be fully qualified. Defining/requesting a permission never grants it. Plan-time validation checks against the provider's published permission inventory. The accepted native license mapping includes LGPL-3.0-only -> native LGPL-3; all other mappings must be explicit rather than dropping license declarations.

Native package X.Y.Z maps to manifest/migration target 19.0.X.Y.Z. `packaging.Version` compares validated canonical versions; full PEP440 specifiers apply to package candidates, never silently to invalid version spellings. Service M.m versions use the single-major range subset in ADR 0003. Ordinary upgrades strictly increase versions. Scripts are under the owning addon's `migrations/<full-native-target>/{pre,post,end}-*.py`; fresh install does not replay upgrade scripts. Actual adjacent/skipped execution is qualified in G5, beyond G2's path/order fixtures.

## Workspace and authority

Authenticated session establishes principal/backing user and server-selected site; workspace-scoped HTTP calls require canonical `X-MP-Workspace`. URL `workspace` query is only a selection request, validated through session context before mounting. Never persist current workspace in shared session state or mutate global backing-user groups for workspace roles. Missing/invalid scope fails closed. Reject `mp_*`/`_mp_*` client context keys on native dataset paths. Typed private native scopes are constructed by the dispatcher; serialized client objects are not scopes.

Global bootstrap routes: `GET /api/v1/session`, `GET /api/v1/workspaces`, login/logout and native session authentication/session-info routes. They require no selected workspace, reveal only current actor's permitted metadata, and provide no business-model dispatch. `GET /api/v1/context` requires workspace and returns current host/session metadata for the registered page. `/app/<plugin_id>/<page_path>?workspace=<uuid>` bootstraps the neutral host. Browser session uses native authentication, HttpOnly/SameSite cookie protection and session CSRF token for non-JSONRPC mutations. No credential is embedded in page URLs. The custom host never exposes native `env`, arbitrary ORM dispatch, administrator cookies or technical tokens.

The shared model mixin enforces live actor/membership/action/feature checks at read/fetch/search/CRUD/public-operation entry, batch ownership and relation preflight, immutable ownership and public IDs. Package qualification requires an indexed owner and a global workspace rule; global domains intersect even a broadened group rule. Private checks are not public RPC methods. Public custom methods must explicitly call the model guard before effects. Legacy dataset call_kw/call_button, native export/import/autocomplete/aggregate and attachment adapters remain subject to shared checks. Unused XML/JSONRPC addons remain omitted. Native export/import and attachment integration tests are G3/G4 requirements; G1 proof is not claimed as their acceptance.

Rule cache includes database/native user, validated workspace and current policy generation. Read current actor/membership/workspace state for every supported operation. Changes bump policy generation transactionally; independent workers read current state. Do not reuse ORM environments/prefetch/results across actor/workspace contexts. Native RPC result cache is disabled in R1. Host context is immutable and generation-scoped; active authority polling is five seconds, with a maximum supported cached/event authorization lifetime of 30 seconds. On visibility resume, revalidate before restoring private content or issuing calls. Aborted/obsolete responses never update another generation. Server authorization precedes any saved-result replay.

Role mappings are frozen in `role-permissions.json`. Workspace-administration capabilities are fully qualified under `org.modularplatform.identity`; other entries are local to their owning plugin. Notes viewer can read; editor and administrator can read/create/update/delete. Workspace administrator additionally manages membership/configuration for that workspace through guarded operations, with no artifact installation/OS authority. Labels/Canvas/analysis mappings are explicit in that file. Service principals require approved actions in addition to membership; there is no administrator fallback. Actor/resource permission, feature/grants, and technical scope intersect. Suspension keeps native schema/data/imports installed; guards stop supported entry points, not arbitrary trusted Python.

## Workspace administrator endpoints

`GET/POST /api/v1/workspace/members` and `GET/POST /api/v1/workspace/settings` require a live human administrator in X-MP-Workspace. POST uses session CSRF and strict workspace-membership/workspace-settings schemas. There is no client-selected workspace/site/backing-user/installation field. Membership commands add/update an existing provisioned principal UUID or revoke its membership; they never provision an account, credential or invitation. Preserve at least one active human administrator. Policy changes serialize on the workspace row, revalidate current authority and increment policy generation. Member listing is bounded to1000 active members; exceeding the supported bound fails explicitly rather than silently truncating. Configuration changes only name/default locale/valid IANA timezone. Use reviewed narrow internal ORM elevation after authorization, with actor/workspace/target/decision/request audit. Native metadata ACLs remain unchanged. GET responses use the same schema file's response definitions. Mutations return only changed target/result so a self-demotion does not reveal the administrator directory afterward. Ordinary read/editor, technical identity, another workspace and application-side operator labels cannot substitute for this role. These additive endpoints do not modify existing DTO/approval/binding meanings.

## Services, bindings and errors

`POST /api/v1/services/<service_id>/<method>` accepts `service-request.schema.json`. Headers: `X-MP-Workspace`, `X-MP-Binding`, optional `X-MP-Consumer` attribution and `X-CSRFToken` for human-session mutations. The locked binding selects consumer/site/workspace/alias/service/major/exact API/provider installation/generation. The server validates all targets against registered metadata and current approval. `X-MP-Consumer`, alias, binding IDs, request IDs and plugin labels confer no authority. SDK `host.services.call(alias,method,input,options)` selects the immutable binding; page options cannot override provider/version/workspace. Optional unresolved bindings return `DEPENDENCY_UNAVAILABLE`. Multiple candidate providers require explicit selection. No automatic latest-major fallback.

Providers register `(service_id, major, plugin_id, installation_id)` exactly once per identity; one provider may offer majors 1 and 2 concurrently. Registry validates allowlisted methods, request/response schema, read/mutation classification, permission and timeout/idempotency metadata. Browser sessions always have null authenticated installation; technical installation comes only from validated credentials. Native call chains retain original actor/site/workspace and intersect grants, never provider-owned wider user authority. `call-context.schema.json` is a host-created DTO, not a client claim. Native ORM environment stays in an internal adapter.

Responses follow `service-response.schema.json`; server UUID request ID is independent of untrusted client correlation. HTTP mapping: UNAUTHENTICATED401, FORBIDDEN403, NOT_FOUND404, VALIDATION_FAILED400, CONFLICT409, DEPENDENCY_UNAVAILABLE503, PLUGIN_SUSPENDED409, RATE_LIMITED429, DEADLINE_EXCEEDED504, CANCELLED409, INTERNAL_ERROR500. Error message <=300 characters; bounded details allow only field/operation/outcome. Unauthorized foreign/nonexistent object IDs both produce NOT_FOUND after current scope/action authorization; no existence oracle. Actor/membership/method denial is FORBIDDEN. No SQL/stack traces or tokens in public errors/logs.

Deadline defaults to 10 seconds, capped at 30 seconds; a caller may shorten it. Cancellation is best effort. A deadline/cancel response carries outcome not_started/committed/unknown when relevant, never asserts rollback from a timeout alone. Idempotency scope is actor/site/workspace/service/major/provider installation/method/key plus exact input digest; persist binding/API/generation. Unique reservation prevents concurrent duplicate effects. Same-database success and effect commit together. Key reused with different input or incompatible rebinding is CONFLICT. In-progress duplicates return CONFLICT plus operation ID/outcome; clients poll/reconcile. Completed results expire after 24 hours by default; after expiry reject the old key and require a new intentional operation rather than silently repeat it. Current authorization is required on replay. External computations/effects require their own dedup/reconciliation; local results are not distributed exactly-once execution.

## Independent plan approval

`plan.schema.json` includes exact operation/targets/base-state/releases/artifacts/dependency lock/binding+endpoint generations/permission+trust changes/destructive/backup/policy/operator-generation. No credentials, arbitrary commands, floats, derived plan hash or approvals. RFC8785 bytes and SHA256 fixture are checked with the pinned library and an independent ECMAScript encoder. Array order is semantic; planner deterministically orders inventories before review.

Only the operator's local CLI approves; OS identity is checked against an operator-owned allowlist outside app DB/backups. Independent CLI recomputes plan/catalog/trust/base-state and displays complete diff. Default start lifetime15min; exact hash plus explicit destructive/trust/permission acknowledgments required. Approval targets/policy/operator generation must match and approval must be unexpired/unrevoked before mutation. Approvals are single-operation reservations; repeat apply resumes/reconciles the same operation, never a second mutation. Operator store/journal outside the DB restore domain, unreadable/unwritable by app identity; app has only authorized redacted status. Exclusive process lock held through mutation, no lease stealing while old process can write. Revocation after mutation stops at a safe boundary and requires reconciliation. Failure/partial commit must say recovery_required until verified restore. G5 proves OS isolation, locks, durable reservation/journal and fault recovery; G2 only freezes these semantics and fixtures.

## External worker

External `.mplug` contains metadata/schemas/notices/inventory/provenance only. Native addon/migrations/Python dependencies/UI/executable installer/deployment descriptor are forbidden. Independently operated Compose image and destination are selected in operator-owned endpoint configuration, never the artifact or browser. Registration/suspension/unregister never starts/stops containers or erases remote storage. Operator verifies immutable image identity; synthetic fixture digests are never deployed.

Endpoint schema permits only operator-allowlisted internal Compose HTTP service:port, health `/health`, bounded request/timeout, fixed issuer/audience/key references, exact site/workspace/installation/method/config generation. R1 reference destination is `http://document-stats:8080`, no URL path/userinfo/query/redirect/proxy supplied by callers. Validate configured destination and resolved peer against the dedicated Compose network/service allowlist; no arbitrary user-selected private destination. Disable redirects and proxy-environment inheritance. Runtime network and configuration verification is G6.

JWT RS256, RSA>=2048, header exactly alg/typ/kid; pinned public key and kid, no remote JWKS/jku/x5u. Required claims in worker-claims schema, lifetime<=300 seconds, nbf=iat, no clock grace. Worker validates standard signature/issuer/audience/times then compares request site/workspace/installation/method/endpoint generation. Key provisioning is independent: private PEM host-only secret, public PEM worker-only verification configuration; rotate by operator configuration generation. Host credential is never exposed to browser and worker receives no DB credential or private issuer key. No callback or human impersonation. Host authorizes before issue, removes revoked endpoint from dispatch immediately, and rechecks originating actor/job authority and expected note revision before applying results. Stateless computation returns only counts; no retained/logged text. Outage is typed degradation and does not bring down host. `/health` returning image identity is not attestation.

## UI lifecycle

`packages/host_sdk/src/index.ts` defines UI major1 and matches snake_case wire DTOs. Pages get only mount subtree, frozen host facade, route snapshot and AbortSignal. Host owns shell routing/history/deep links, context generation and native adapter. Same page route changes call updateRoute; workspace/identity/binding/authority changes dispose+abort+remount. Dispose removes subscriptions/handlers/timers/observers; host stops event delivery and drops obsolete asynchronous results, including completed transports awaiting callbacks. Native views get the workspace header through the adapter; native internals never enter custom facade. R1 custom page remains fully trusted same-origin code.

Host handles mount failure with correlation ID and explicit retry/back; no reload loop. canLeave confirm is honored for dirty navigation where feasible. Session expiry blocks business calls and offers safe draft recovery without indiscriminate sensitive storage. Immersive mode always has accessible host exit. Theme/locale subscriptions are generation-bound. Commands and navigation use registered allowlists, not arbitrary URLs/JS. Core reference slot `org.example.notes:slot:detail_actions` major1 receives only public note ID/revision and an action callback; Labels declares hard dependency, unique contribution ID and deterministic order. Canvas consumes declared `documents` alias rather than ORM. These behaviors are qualified at G3/G4, beyond G1's minimal lifecycle feasibility.

## Changes and ownership

Revision4 (ADR0006) adds optional strict manifest UI slots/contributions/commands, documents2.0, boards1.0 and composition examples. `resolve_ui` validates ownership/dependencies/slot majors and orders contributions without importing code. Missing/incompatible required slots, unknown/cross-slot ordering references and cycles fail; optional incompatible contributions alone are omitted. Same-order ties sort by plugin ID then contribution ID. Compiled handler registry IDs are allowlisted from activated manifests; metadata strings never execute. Detail-action context is `note_id`/`expected_revision` only. Documents1.0 remains unchanged; documents2.0 read-only DTOs use `document_id`/`content`. Labels binds major1, Canvas major2. Revision5 permits omitted board_id on boards.get to select the single reference board in the explicitly selected workspace; explicit foreign/unknown IDs are not found. It never selects a workspace. Boards use40 ordered cards,200-character text, same-workspace note references, unique card IDs and revision-CAS save. Supported nested calls preserve actor/site/workspace and intersect current actor/method/model/installation/feature/integration authority. See ADR0006 for native extension field/suspension and cancellation outcomes.

G2 freezes public meaning; G3 identity/Notes/gateway/shell, G4 extension/Canvas/slots, G5 packages/solver/executor and G6 jobs/outbox/worker own full acceptance. G7 requalifies integration and release/runbooks. Breaking schema/semantics introduce a public major; compatible additions update protocol minor/inventory with ADR, consumers/fixtures and affected evidence. Changing authority/tenancy/approval interpretation cannot be labelled an internal refactor. Retire mp_feas from production distribution when reusable adapters are integrated; keep it as a regression fixture, not an installed R1 application.

Revision6/ADR0007 adds optional synchronous MountedPage.snapshotDraft() for custom recovery before abort/dispose. The host validates filename/JSON and65536-byte encoding, binds principal/site/workspace, holds it in RAM and offers explicit download; new actor/site or known scope denial clears it. No automatic persistence/download. Existing pages without the hook remain valid.

## Operator request/status API (revision7)

`operations-request` and `operations-view` define the additive routes/authority in ADR0009. Only a current explicitly provisioned human application operator prepares/requests/views site operations; workspace administrator status and service identities do not confer that role. Browser mutations require session CSRF and bounded strict JSON. Preparation nominates exact package version/digest and explicit site/workspace IDs/cascade, then returns the unchanged v1 plan and exact proposed targets. Native uninstall/unregister/removal are site operations. A request carries operation ID/hash/request ID, never an approval/credential/command. Restore preparation stays the local recovery CLI. The complete operation-lock preimage is retained for independent OS-side retrieval/reconstruction. UI metadata and journal mirrors are untrusted; their source/time/staleness and five separate lifecycle dimensions are explicit. Native suspension does not unload code. Local OS approval authenticates the exact independently recomputed plan; app roles/flags and copied IDs cannot authorize or reveal control-store data. No privileged web approval endpoint is introduced.

All anchored JSON-schema patterns use a portable absolute-end negative lookahead to reject a terminal newline. This corrects canonical identifier/digest/version intent; valid fixtures and the golden plan hash remain unchanged. The UI-view validator additionally checks plan ID/hash/target/trust/restart consistency and prevents an application-request observation from asserting operator approval. It does not authenticate a journal mirror. Existing G4 runtime remains its qualified prior image; new consumer runtime checks are qualified at G5/G7.
